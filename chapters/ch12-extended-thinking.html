Extended Thinking / Reasoning

General AI Eng giving the model a scratchpad to reason in before it commits to an answer

Why this matters. Chapter 8 showed that asking a model to "think step by step" in the prompt improves accuracy on hard problems. Extended thinking is a built-in, more powerful version of that same idea — the model generates a visible reasoning trace in a dedicated "thinking" block before its actual answer, with a controllable token budget. It's the right tool for genuinely hard problems, and the wrong tool (too slow, too expensive) for simple ones.

Real-world analogy

Chain-of-thought prompting (Ch. 8) is like asking someone to "show your work" on a math test — they write it in the same notebook as their final answer. Extended thinking is more like giving them dedicated scratch paper explicitly separate from their answer sheet, and telling them how much scratch paper they're allowed to use before they must commit to a final answer.

1. What actually happens

Normal response: ┌────────────────────────────────────┐ │ Final answer, straight away │ └────────────────────────────────────┘ Extended thinking: ┌────────────────────────────────────┐┌──────────────────────┐ │ THINKING BLOCK (internal reasoning) ││ Final answer, │ │ "Let me work through this... first ││ informed by the │ │ I need to check X, then Y implies ││ reasoning above │ │ Z, so the answer should be..." ││ │ └────────────────────────────────────┘└──────────────────────┘ costs tokens, not shown to end-user by default (you choose whether to surface it)

2. Code example

const response = await client.messages.create({
  model: "claude-sonnet-5",
  max_tokens: 2000,
  thinking: {
    type: "enabled",
    budget_tokens: 1024, // max tokens the model can spend "thinking"
  },
  messages: [{
    role: "user",
    content: "A train leaves station A at 60mph, another leaves station B " +
              "(300 miles away) at 40mph toward A, 30 minutes later. When do they meet?",
  }],
});

// response.content contains both a "thinking" block and the final "text" block
const thinking = response.content.find(b => b.type === "thinking");
const answer = response.content.find(b => b.type === "text");

3. When to turn it on

Good fitNot worth it
Multi-step math, logic puzzles, complex planningSimple factual lookups ("what's the capital of X")
Code that requires reasoning through edge casesShort creative writing or casual chat
Ambiguous requests needing careful disambiguationHigh-volume, latency-sensitive endpoints (Ch. 15)
Tasks where being wrong is costly (financial, legal analysis)Anything where a fast, "good enough" answer is fine
The tradeoff, in one line: extended thinking spends more tokens (cost) and time (latency) to buy higher accuracy on hard problems. Turning it on for every request is like hiring a careful auditor to double-check your grocery list — technically thorough, but wasteful for the task.

4. Extended thinking vs. the agent loop (Ch. 14)

Don't confuse these: extended thinking is reasoning within a single model turn, before it writes its answer. The agent loop (Chapter 14) is reasoning across multiple turns, interleaved with actual tool calls and real-world observations. A complex agent can use both — thinking carefully within each step, while also looping across several steps.

Key takeaways

  • Extended thinking gives the model a dedicated reasoning trace, generated before its final answer, with a controllable budget_tokens.
  • It's a more structured, built-in version of "think step by step" chain-of-thought prompting (Ch. 8).
  • Use it for genuinely hard, multi-step, or high-stakes problems — not for simple lookups or casual chat.
  • The cost is real: more tokens spent, more latency — always a deliberate tradeoff, not a default-on setting.
  • It reasons within one turn; the agent loop (Ch. 14) reasons across multiple turns with real tool calls.
