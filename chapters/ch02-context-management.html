Context Management

Claude CodeGeneral AI Eng compaction · /clear · long sessions · token budgeting

Why this matters. An LLM has no memory between calls. Everything it "knows" in a session is re-sent every turn as the context window — a fixed token budget. Manage it well and Claude stays sharp and cheap; manage it badly and it gets slow, expensive, and forgetful. This is the #1 skill for long agent sessions.

Real-world analogy

The context window is a whiteboard, not a filing cabinet. Everything the model reasons about must fit on the board right now. When it fills up, you either erase and start fresh (/clear) or summarize the board into a corner and wipe the rest (compaction). A cluttered whiteboard makes even a genius slow.

What's actually in the context window

Every turn, the model receives (and you pay for) roughly:

  • System prompt + tool definitions
  • CLAUDE.md and any loaded memory
  • The full conversation so far (your messages + Claude's + every tool result)
  • Files you've read, command outputs, search results

Tool results are the silent budget-killer: reading a 2,000-line file or dumping a huge log injects thousands of tokens that stay for the rest of the session.

Compaction — summarize and continue

When context nears the limit, Claude Code compacts: it summarizes the older conversation into a compact form and continues with that summary plus recent messages. You can trigger it manually with /compact, optionally with guidance:

/compact focus on the auth refactor and the failing test; drop the file dumps

Compaction preserves continuity (you don't lose the thread) but is lossy — fine detail can be dropped. That's why leaving instructions helps.

/clear — wipe and restart

/clear throws away the whole conversation and starts fresh (CLAUDE.md still reloads). Use it when you switch to an unrelated task. The trap: people keep one giant session all day, so context is full of irrelevant history that confuses the model and inflates cost.

Token budgeting as a discipline

Treat context like RAM. Practical habits:

  • Read narrowly. Grab the function you need, not the whole 3,000-line file.
  • Delegate heavy reads to subagents. A subagent (Chapter 5) reads a lot, returns a short summary — the bulk never touches your main context.
  • Keep CLAUDE.md lean. It's re-sent every turn.
  • Clear between tasks. Don't hoard history.
  • Watch the context meter. Compact proactively before it auto-triggers mid-thought.
Connects forward: This is the CC-flavored version of a general skill called context engineering (Chapter 14) — deciding what information the model sees at each step. Same idea whether you're in the CLI or building your own agent.

Key takeaways

  • The context window is re-sent every turn — it's your token budget, not free memory.
  • Tool results (big file/command outputs) are the main hidden cost.
  • /compact = summarize & keep going (lossy); /clear = wipe for a new task.
  • Read narrowly, delegate heavy reads, keep CLAUDE.md lean, clear between tasks.
  • It's the practical face of context engineering — a discipline, not an afterthought.
