🧠 Model & Architecture

TokenThe smallest unit of text a model processes — a word, part of a word, or punctuation mark. Not the same as a letter or a whole word.Ch. 0a
TokenizationThe process of chopping text into tokens before feeding it to the model.Ch. 0a
EmbeddingA list of numbers (a vector) that represents the "meaning" of a token, word, sentence, or document as a position in space.Ch. 0a, 16
VectorJust a list of numbers — the mathematical form an embedding takes (e.g. [0.12, -0.98, 0.44, ...]).Ch. 0a, 16
DimensionsHow many numbers are in an embedding vector (e.g. 1536 dimensions = a list of 1536 numbers). More dimensions can capture more nuance in meaning, at a storage/compute cost.Ch. 16
Vector space / embedding spaceThe imaginary multi-dimensional "map" where embeddings live — things with similar meaning end up positioned close together.Ch. 0a, 16
Cosine similarityThe standard way to measure "how close" two embedding vectors are (i.e. how similar their meaning is) — it measures the angle between them, not their distance. Score of 1 = identical direction/meaning, 0 = unrelated, -1 = opposite.Ch. 16
AttentionThe mechanism that lets a model weigh how relevant every other token is when interpreting a given token (e.g. resolving what a pronoun refers to).Ch. 0a
Self-attentionAttention applied within a single sequence — tokens attending to other tokens in the same input, which is what regular "attention" in an LLM usually means.Ch. 0a
TransformerThe neural network architecture (built from stacked attention + feed-forward layers) that powers virtually every modern LLM, including Claude, GPT, and Gemini.Ch. 0a
Parameters / weightsThe billions of internal numbers a model learns during training — they encode everything the model "knows." "70B parameters" means 70 billion of these numbers.Ch. 0b
Context windowThe maximum number of tokens (input + output combined) a model can "see" at once in a single conversation/request.Ch. 2
MultimodalA model that can accept more than one type of input (e.g. text + images), even if it only outputs one type (e.g. Claude reads images but only writes text back).Ch. 0d, 7

🎓 Training

PretrainingThe first, most expensive training stage — the model learns to predict the next token over trillions of words of text, absorbing language and knowledge as a side effect.Ch. 0b
Base modelA model that's only been pretrained, with no fine-tuning — knowledgeable, but doesn't behave like a well-mannered assistant yet.Ch. 0b
Fine-tuning / SFT (Supervised Fine-Tuning)A lighter second training stage where the model is shown curated "question → ideal answer" examples, teaching it to act like a helpful assistant.Ch. 0b
RLHF (Reinforcement Learning from Human Feedback)A training stage where humans (or a reward model standing in for them) rank multiple model answers, nudging the model toward the style people actually prefer.Ch. 0b
Reward modelA smaller model trained to predict how a human would rate a given answer, used to guide RLHF at scale without a human rating every single response.Ch. 0b
Constitutional AIAnthropic's technique where a model critiques and revises its own answers against a written set of principles, reducing how much raw human labeling RLHF needs.Ch. 0b
AlignmentThe general goal of making a model's behavior match human intentions and values — SFT and RLHF are both alignment techniques.Ch. 0b
Instruction tuningAnother name for the SFT process of teaching a base model to follow instructions rather than just continue text.Ch. 0b
LoRA (Low-Rank Adaptation)A cheap way to fine-tune a model by training a small set of additional parameters instead of updating all of the model's original weights.Ch. 21
HallucinationWhen a model confidently generates false or made-up information — a natural side effect of it being a probability-based text predictor, not a database.Ch. 0b, 28

🎲 Generation & Sampling

Logits / probability distributionThe model's raw output at each step — a score (turned into a probability) for every possible next token.Ch. 0c
SamplingThe process of actually picking one token from that probability distribution to generate next.Ch. 0c
TemperatureA setting that reshapes the probability distribution before sampling: 0 = always pick the most likely token (deterministic), higher = more variety and risk.Ch. 0c
Top-p (nucleus sampling)Only samples from the smallest set of top tokens whose probabilities add up to p (e.g. 0.9), excluding the improbable "long tail."Ch. 0c
Top-kOnly samples from the k highest-probability tokens by rank, ignoring everything else.Ch. 0c
Greedy decodingThe special case of temperature = 0 — always picking the single highest-probability token, giving fully deterministic output.Ch. 0c
max_tokensAn API parameter that hard-caps how many tokens a reply can contain, cutting it off if it hits the limit.Ch. 0c, 15
Stop sequenceA custom string that, if generated, immediately ends the model's output (e.g. stopping at a specific delimiter).Ch. 0c
StreamingReceiving a model's response token-by-token as it's generated, instead of waiting for the entire reply to finish.Ch. 13

✍️ Prompting

System promptInstructions given to the model before the conversation starts, setting its role, tone, and constraints for the whole session.Ch. 8
Few-shot / zero-shotFew-shot = giving the model 2–3 worked examples in the prompt to show the exact output shape you want. Zero-shot = no examples, just instructions.Ch. 8
Prompt engineeringThe practice of designing prompts (system prompts, examples, structure) to reliably steer a model's behavior without changing its weights.Ch. 8
Chain-of-thoughtPrompting the model to reason step-by-step before giving a final answer, which often improves accuracy on complex problems.Ch. 8, 12
Extended thinking / reasoningA model mode where it generates an internal "thinking" trace before answering, useful for harder problems at the cost of extra tokens/latency.Ch. 12
Structured outputForcing a model's response into a specific format (usually JSON) matching a schema you define, so downstream code can parse it reliably.Ch. 9
Prompt cachingReusing the processed representation of a repeated prompt prefix across requests, cutting cost and latency for large, unchanging context (like a big system prompt).Ch. 10

🛠️ Tools & Agents

Tool use / function callingGiving a model a set of defined functions it can request to call (with arguments), letting it take actions or fetch live data beyond its training knowledge.Ch. 11
MCP (Model Context Protocol)An open standard that packages tools/data/prompts into a portable "server" any compatible AI app can plug into — like a USB-C port for AI tools.Ch. 4
Agent loopThe repeating cycle of plan → act (use a tool) → observe the result → repeat, that lets a model complete multi-step tasks autonomously.Ch. 14
SubagentA separate agent instance, with its own context window, delegated a specific sub-task by a parent agent — only the final summary comes back.Ch. 5
Claude Agent SDKA library exposing the same agent engine that powers Claude Code (loop, tools, permissions, MCP) so you can build standalone agents outside the CLI.Ch. 6
Computer useLetting a model operate a screen directly — screenshot in, click/type actions out — used when no clean API exists for a task.Ch. 7

📚 RAG & Retrieval

RAG (Retrieval-Augmented Generation)Feeding a model relevant chunks of your own documents/data at query time, so it can answer using information it wasn't trained on.Ch. 16–21
Embedding modelA (usually smaller, specialized) model whose only job is to turn text into embedding vectors for search/retrieval, as opposed to generating text.Ch. 16
ChunkingSplitting a large document into smaller pieces before embedding/storing it, so retrieval can pull back just the relevant part instead of the whole document.Ch. 17
Vector database / vector storeA database optimized for storing embeddings and quickly finding the ones most similar to a query vector (e.g. pgvector, Pinecone, Chroma, Qdrant).Ch. 18
Semantic searchSearching by meaning (via embeddings/cosine similarity) rather than exact keyword matching.Ch. 19
Hybrid searchCombining semantic (vector) search with traditional keyword search to get the strengths of both.Ch. 19
RerankingA second pass that re-scores an initial set of retrieved results with a more precise (but slower) model, pushing the truly best matches to the top.Ch. 19
Agentic RAGRAG where the model itself decides when/what to retrieve, possibly across multiple rounds, instead of a single fixed retrieval step.Ch. 20
GraphRAGA RAG variant that retrieves from a knowledge graph (entities + relationships) instead of, or alongside, flat document chunks.Ch. 20

🕸️ Orchestration Frameworks

LangChainA framework providing pre-built abstractions (chains, memory, retrievers) for building LLM applications, overlapping with native tool-use patterns.Ch. 22
LangGraphA graph-based orchestration framework for building agents as state machines, supporting cycles, branching, and human-in-the-loop steps.Ch. 23
Multi-agent systemMultiple specialized agents coordinating on a task, often with one orchestrator agent delegating to worker agents.Ch. 24
Orchestrator / worker patternA common multi-agent design where one "orchestrator" agent plans and delegates sub-tasks to specialized "worker" agents.Ch. 24

🛡️ Safety, Evaluation & Production

GuardrailsInput/output checks (validation, filtering, schema enforcement) that constrain what a model is allowed to receive or produce.Ch. 25
Prompt injectionAn attack where malicious text hidden in a document, webpage, or tool result tricks a model into ignoring its real instructions.Ch. 7, 26
PII redactionAutomatically detecting and removing/masking personally identifiable information (names, emails, SSNs) from text before it's stored or sent onward.Ch. 27
Eval (evaluation)A structured test set + scoring method used to measure how well a model or pipeline performs, and to catch regressions when you change something.Ch. 28
LLM-as-judgeUsing one model to automatically grade/score another model's outputs against criteria, as a scalable substitute for human review.Ch. 28
Observability / tracingLogging and visualizing every step of an agent/LLM pipeline's execution (prompts, tool calls, latencies) to debug and monitor it in production.Ch. 29
Red-teamingDeliberately attacking your own AI system to find safety and security weaknesses before real adversaries do.Ch. 30
LatencyThe time it takes to get a response back from a model — a key production concern, especially for streaming/agentic workflows.Ch. 15
Rate limitA cap on how many requests/tokens per minute an API account can send, which production systems must handle with retries/backoff.Ch. 31

⚙️ Claude Code Specific

CLAUDE.mdA markdown file Claude Code automatically loads every session, giving it persistent project context/instructions ("project memory").Ch. 1
Slash commandA saved, reusable prompt triggered by typing /name, stored in .claude/commands/.Ch. 1
HookA deterministic shell command that runs automatically on a Claude Code event (e.g. before a tool call) — a "guarantee" vs. CLAUDE.md's "suggestion."Ch. 1
Settings.jsonClaude Code's configuration file for permissions, hooks, and environment variables, with user/project/local precedence layers.Ch. 1
Permission modeThe current operating mode governing what Claude Code can do without asking (default, acceptEdits, plan, bypassPermissions).Ch. 1
SkillA single, on-demand capability defined in a SKILL.md file, loaded into context only when relevant (progressive disclosure).Ch. 3
PluginA distributable bundle that can package skills, slash commands, MCP servers, subagents, and hooks together.Ch. 3
CompactionLossy summarization of older conversation turns to free up context window space, triggered by /compact or automatically near the limit.Ch. 2
