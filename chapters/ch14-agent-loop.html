Agent Loop Engineering

General AI Eng the pattern that turns single tool calls (Ch. 11) into an agent that completes real multi-step tasks

Why this matters. Every "AI agent" you've used — Claude Code included — is built around one core pattern repeated over and over: plan, act, observe, repeat. Understanding this loop demystifies what an "agent" actually is (it's not magic — it's a while-loop around a model with tools) and is the foundation for building your own.

Real-world analogy

Think of a chef cooking a dish they've never made before, from a recipe card with steps but no fixed order guaranteed to work: taste (observe), decide what's missing (plan), add an ingredient (act), taste again (observe), repeat — until the dish is done. A single tool call (Ch. 11) is one "taste and add ingredient." The agent loop is the chef doing that repeatedly, using each result to decide the next move, until the dish is actually finished.

1. The loop, step by step

┌─────────────────────────────────────────┐ │ │ ▼ │ 1. PLAN — model decides what to do next │ │ (answer now? or use a tool?) │ ▼ │ 2. ACT — if a tool is needed, your code executes it │ │ │ ▼ │ 3. OBSERVE — tool result is sent back to the model │ │ │ ▼ │ 4. Model decides: task complete? ── NO ──────────────┘ │ YES ▼ 5. Return final answer to the user

2. A minimal agent loop in code

async function runAgent(userTask, tools, toolHandlers) {
  let messages = [{ role: "user", content: userTask }];
  const MAX_STEPS = 10; // always cap it — see "stopping conditions" below

  for (let step = 0; step < MAX_STEPS; step++) {
    const response = await client.messages.create({
      model: "claude-sonnet-5",
      max_tokens: 1000,
      tools,
      messages,
    });

    messages.push({ role: "assistant", content: response.content });

    const toolUse = response.content.find(b => b.type === "tool_use");
    if (!toolUse) {
      // no tool requested → model is done, this is the final answer
      return response.content.find(b => b.type === "text").text;
    }

    // OBSERVE: run the tool, feed the result back in, loop again
    const result = await toolHandlers[toolUse.name](toolUse.input);
    messages.push({
      role: "user",
      content: [{ type: "tool_result", tool_use_id: toolUse.id, content: JSON.stringify(result) }],
    });
  }
  throw new Error("Agent exceeded max steps without finishing");
}

3. Stopping conditions — don't let it run forever

ConditionWhy it matters
Max steps (like MAX_STEPS above)Prevents infinite loops from a confused or stuck agent — always set a hard ceiling
No tool_use in responseThe natural "done" signal — the model believes it has a final answer
Max token/cost budgetCaps runaway spending on a single task (ties into Ch. 15)
Explicit "give up" toolSome agents get a tool like ask_human or report_blocked so they can stop gracefully instead of looping uselessly

4. Context engineering: the loop's context grows every step

Notice that messages keeps growing — every tool call and result gets appended. Left unmanaged, a long-running agent will eventually blow through the context window (Chapter 2). "Context engineering" is the practice of deliberately managing what stays in that growing list: summarizing old steps, dropping large tool outputs once they're no longer needed, or compacting history — the same ideas from Chapter 2, applied specifically to an agent's working memory instead of a chat conversation.

5. This is what Claude Code and subagents already do for you

You've been using an agent loop this whole time without writing one — Claude Code's own interaction model is this loop (plan → call a tool like Read/Edit/Bash → observe the result → repeat), and subagents (Ch. 5) run their own independent copy of it. This chapter is what's happening under the hood every time Claude Code reads a file, runs a command, and decides what to do next based on the result.

Key takeaways

  • The agent loop is plan → act → observe → repeat — a while-loop wrapped around the single tool-use round trip from Chapter 11.
  • The loop ends when the model responds with no further tool requests, or when a stopping condition (max steps, budget) is hit.
  • Always set a hard step/cost ceiling — an unattended loop can run indefinitely or expensively without one.
  • Context engineering — managing the growing message history — becomes essential for any agent that runs more than a few steps.
  • Claude Code itself, and every subagent (Ch. 5) it spawns, is an implementation of exactly this loop.

Understanding check
  1. What are the four steps of the agent loop? Plan (decide what to do), act (execute a tool if needed), observe (feed the result back), and repeat until no more tool calls are requested.
  2. Why is a max-step limit essential in any real agent loop? Without one, a confused or stuck agent can loop indefinitely, burning time and cost with no natural stopping point.
