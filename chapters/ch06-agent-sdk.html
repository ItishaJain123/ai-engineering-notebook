Claude Agent SDK

Claude CodeGeneral AI Eng building standalone agents outside the CLI

Why this matters. Claude Code the CLI is one product. Under it sits an agent engine — the loop, tool use, permissions, subagents, context management — that Anthropic exposes as the Claude Agent SDK (TypeScript & Python). It lets you build your own agents (a code-fixing bot in CI, a Slack helper, a background worker) that reuse the same battle-tested machinery instead of writing an agent loop from scratch.

Real-world analogy

Claude Code is a finished car. The Agent SDK is the engine + chassis sold on its own, so you can build a truck, a boat, or a go-kart on the same drivetrain. You skip re-inventing the engine (the agent loop, tool routing, permissions) and focus on the body (your product).

What the SDK gives you

  • The agentic loop (plan → call tools → observe → repeat) managed for you.
  • Built-in tools: file read/write, shell, search — the same ones Claude Code uses.
  • MCP support (Chapter 4), subagents (Chapter 5), permissions, hooks, and context/compaction handling.
  • Runs headless (no terminal UI) — perfect for servers, CI, cron jobs.

Minimal agent in JavaScript

npm install @anthropic-ai/claude-agent-sdk
# set ANTHROPIC_API_KEY in your environment
import { query } from "@anthropic-ai/claude-agent-sdk";

// query() returns an async stream of messages from the agent loop
const response = query({
  prompt: "List the .js files in this folder and summarize what each does.",
  options: {
    model: "claude-sonnet-5",
    allowedTools: ["Read", "Glob", "Grep"],   // least privilege
    permissionMode: "acceptEdits"
  }
});

for await (const msg of response) {
  if (msg.type === "assistant") {
    for (const block of msg.message.content) {
      if (block.type === "text") process.stdout.write(block.text);
    }
  }
}

Notice the shape: you give a prompt + options (model, which tools it may use, permission mode), then stream the agent's messages as it works. You control the blast radius with allowedTools — least privilege, just like a hook or MCP scope.

Add your own tool

You can register custom in-process tools (or wire an MCP server). Conceptually:

options: {
  mcpServers: {
    math: { command: "node", args: ["./math-mcp/server.js"] }  // reuse Ch.4!
  }
}

Your Chapter 4 MCP server drops straight into an SDK agent — that's the payoff of a standard protocol.

Agent SDK vs. raw Claude API vs. Claude Code CLI

OptionYou writeBest for
Raw Claude API (@anthropic-ai/sdk)The whole agent loop yourselfFull control, simple single-shot calls, custom orchestration
Claude Agent SDKJust the task + configAutonomous agents that use files/tools, headless, in production
Claude Code CLINothing — you drive itInteractive dev work in your terminal
Rule of thumb: single request/response → raw API. An autonomous helper that reads files, runs tools, and loops until done → Agent SDK. A human coding interactively → the CLI.

Key takeaways

  • The Agent SDK exposes Claude Code's engine so you can build custom, headless agents.
  • You provide a prompt + options (model, allowedTools, permissionMode) and stream messages.
  • It reuses MCP, subagents, permissions, and context handling — no DIY agent loop.
  • Scope tools tightly (allowedTools) for safety.
  • Raw API = you build the loop; Agent SDK = loop provided; CLI = interactive use.

  2. For each, pick raw API / Agent SDK / CLI and justify: (a) a nightly job that fixes lint errors and opens a PR, (b) a function that classifies a support email's sentiment, (c) you refactoring code live in your terminal.
  3. Stretch: if you built the Ch.4 MCP server, wire it into an SDK agent via mcpServers and have the agent call it.
Understanding check
  1. When would you choose the raw Claude API over the Agent SDK? When you only need a single request/response or want to hand-build a custom loop — no autonomous file/tool looping needed.
  2. How do you limit what a standalone agent can do? Scope allowedTools and set an appropriate permissionMode (least privilege).
