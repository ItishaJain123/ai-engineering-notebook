🟢 Agent SDK in plain English (read this first)

Claude Code — the tool you're chatting with right now — isn't magic glued directly to a terminal. Underneath, there's a reusable agent engine: the loop that reads your request, decides to use a tool, checks the result, and repeats until done. The Claude Agent SDK is Anthropic handing you that same engine, so you can build your own app powered by it — not just use it inside a terminal chat.

Tiny example: imagine you want a bot that runs every night, reads your codebase, fixes lint errors, and opens a pull request — with nobody typing anything into a terminal. You can't use "Claude Code the CLI" for that (it needs a human typing). But you can write a small script using the Agent SDK that does exactly this, unattended.

Remember 3 things: (1) Claude Code CLI = the engine + a terminal chat interface built on top, for humans. (2) Agent SDK = the same engine, without the chat interface, for your own programs. (3) You still get tool use, MCP, subagents, permissions — all of it — just callable from your own code.

Why this matters (the technical version). Building an agent loop from scratch — deciding when to call a tool, feeding results back, managing context, enforcing permissions — is genuinely hard and easy to get wrong. The Agent SDK (TypeScript & Python) gives you that battle-tested engine as an importable package, so you focus on your product (a CI bot, a Slack helper, a background worker) instead of reinventing the loop.

Real-world analogy

Claude Code is a finished car — engine, seats, steering wheel, ready to drive. The Agent SDK is the engine + chassis sold on its own, so you can build a truck, a boat, or a go-kart on the same drivetrain. You skip reinventing the engine (the agent loop, tool routing, permissions) and just build the body — your product.

What the SDK actually gives you

  • The agentic loop, already built: plan → call a tool → look at the result → repeat until done.
  • The same built-in tools Claude Code uses — reading/writing files, running shell commands, searching.
  • Everything you've already learned: MCP (Chapter 4), subagents (Chapter 5), permission controls, and automatic context/compaction handling.
  • It runs headless — no chat window, no human needed — which is exactly what a server, a CI pipeline, or a nightly cron job needs.

A minimal agent, step by step

Step 1 — install it and set your API key:

npm install @anthropic-ai/claude-agent-sdk
# set ANTHROPIC_API_KEY in your environment

Step 2 — write the agent. You give it a task (prompt) and some rules (options), then read back what it does as it works:

import { query } from "@anthropic-ai/claude-agent-sdk";

// query() starts the agent loop and streams back messages as it works
const response = query({
  prompt: "List the .js files in this folder and summarize what each does.",
  options: {
    model: "claude-sonnet-5",
    allowedTools: ["Read", "Glob", "Grep"],   // it may ONLY read & search — no editing, no shell
    permissionMode: "acceptEdits"
  }
});

// stream the agent's replies as they arrive, instead of waiting for everything at once
for await (const msg of response) {
  if (msg.type === "assistant") {
    for (const block of msg.message.content) {
      if (block.type === "text") process.stdout.write(block.text);
    }
  }
}

What's happening, in order:

  1. prompt is the job — plain English, exactly like what you'd type into Claude Code.
  2. allowedTools is a safety leash — this agent is only allowed to read and search files, never edit or run shell commands. This is the same "least privilege" idea as scoping an MCP server (Chapter 4) or a subagent's tools field (Chapter 5).
  3. Calling query(...) kicks off the loop: it may read a file, look at the result, decide to read another, and so on — all without you writing that loop yourself.
  4. The for await loop is how you watch it work in real time, message by message, instead of waiting silently until it's fully done.
Understanding check yourself: if you changed allowedTools to just ["Read"] (dropped Glob and Grep), the agent could open a file you name — but it could no longer search for which files exist. Same idea as taking away someone's ability to browse a filing cabinet, while still letting them read any specific folder you hand them.

Give your agent an MCP tool (reusing Chapter 4)

Remember the little MCP math server you could build in Chapter 4? It drops straight into an SDK agent — no rewrite needed. That's the whole payoff of MCP being a standard: build a tool once, plug it in anywhere.

options: {
  mcpServers: {
    math: { command: "node", args: ["./math-mcp/server.js"] }  // reuse Ch.4!
  }
}

Three ways to talk to Claude — which one do you want?

Beginners often mix these three up. Here's the difference in one sentence each:

OptionIn one sentenceYou writeBest for
Raw Claude APIYou send one message, get one reply — you decide what happens next.The whole agent loop yourself, if you want oneSimple single-shot calls, full custom control
Claude Agent SDKYou describe a task; it loops on its own using tools until finished.Just the task + a few settingsAutonomous agents in production — CI bots, background workers
Claude Code CLIYou chat with it directly in your terminal, like right now.Nothing — you drive it liveInteractive coding with a human at the wheel
Analogy: raw API is texting a friend one question at a time. Agent SDK is giving an assistant a full task list and letting them work through it unsupervised. Claude Code CLI is sitting next to that assistant, pointing at the screen as they work.
Simple rule to decide: need just one answer back? → raw API. Need something that reads files/runs tools/keeps going until the job's done, with nobody watching? → Agent SDK. Are you a person typing into a terminal right now? → CLI (which is what you're using with me).

Key takeaways

  • The Agent SDK is Claude Code's engine, made available for your own programs — no chat window needed.
  • You give it a prompt + options (model, allowedTools, permissionMode), and it streams back messages as it works.
  • It reuses everything you already learned — MCP servers, subagents, permission scoping, context handling — no DIY loop required.
  • Always scope allowedTools as tightly as the task allows — least privilege.
  • One answer back → raw API. Autonomous multi-step work → Agent SDK. A human typing live → the CLI.

Understanding check
  1. When would you choose the raw Claude API over the Agent SDK? When you only need one request/response, or want to hand-build your own custom loop — no autonomous multi-step tool use needed.
  2. How do you limit what a standalone agent is allowed to do? Scope allowedTools to only what's needed, and set an appropriate permissionMode — least privilege.
  3. Why can't you use the Claude Code CLI for a nightly automated job? The CLI is built for a human typing interactively — an unattended nightly job needs the headless Agent SDK instead.
