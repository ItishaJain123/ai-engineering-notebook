Part 0 · Chapter 0c

Sampling & Generation Parameters

General AI Eng temperature, top-p, top-k — the knobs you actually control via the API

Why this matters. This is the most practical chapter in Part 0 — unlike training (Ch. 0b), which you never touch, these parameters are ones you set on every single API call. Getting them right is the difference between a chatbot that feels robotic/repetitive and one that feels natural, or between a data-extraction pipeline that's reliably consistent and one that randomly breaks.

1. Remember from Chapter 0a: the model outputs probabilities, not a word

At each step, the model doesn't directly output "the next word is pizza." It outputs a probability for every possible next token — thousands of them. Something has to pick one. That picking process is called sampling, and the sampling parameters control how it's done.

Prompt: "My favorite food is" Model's raw output (a probability distribution over next tokens): ┌──────────┬────────┐ │ "pizza" │ 41% │ ████████████████████ │ "sushi" │ 22% │ ███████████ │ "pasta" │ 15% │ ███████ │ "tacos" │ 9% │ ████ │ "kale" │ 1% │ ░ │ ... (thousands more, tiny probabilities) │ └──────────┴────────┘ Sampling = "which one do we actually pick?"

2. Temperature — how "risky" the pick is

Temperature reshapes that probability distribution before picking. Low temperature squashes it toward the top choice (more predictable, more repetitive); high temperature flattens it out (more variety, more surprising, occasionally weirder).

temperature = 0 → always pick "pizza" (the single highest-probability token) (deterministic — same input always gives same output) temperature = 0.7 → mostly "pizza", sometimes "sushi" or "pasta" (the sweet spot for most chat/writing use cases) temperature = 1.5 → distribution flattened — "kale" becomes a real possibility (creative, unpredictable, sometimes incoherent)
Analogy: temperature is like how "adventurous" someone is when picking a restaurant. At temperature 0, they always go to their #1 favorite place, every single time — reliable, boring. At high temperature, they'll sometimes pick their 5th favorite just to mix it up — more interesting, occasionally a bad night.

3. Top-p (nucleus sampling) — cut off the long tail

High temperature alone has a problem: it gives real probability to genuinely bad/nonsensical tokens sitting way down in the "long tail." Top-p (a.k.a. nucleus sampling) fixes this by only considering the smallest set of top tokens whose probabilities add up to p — then samples (with temperature) only from that shortlist.

top_p = 0.9 → keep adding tokens by probability until we hit 90% of the total mass: "pizza" 41% + "sushi" 22% + "pasta" 15% + "tacos" 9% = 87% → still adding + "kale" 1% + ... more small ones ... = 90% → STOP, this is our shortlist Only these tokens are eligible to be picked — the 1000s of near-zero-probability tokens ("bicycle", "Tuesday", gibberish) are excluded entirely, no matter how high temperature is set.

Top-k is the simpler cousin: instead of a probability cutoff, it just keeps the top k tokens by rank (e.g. top-k=40 = only the 40 most likely tokens are eligible). Most APIs, including Claude's, let you set top_p, and some let you set top_k too — you rarely need both at once.

4. What this looks like in real code

Here's an actual Claude API call showing where these knobs live:

import Anthropic from "@anthropic-ai/sdk";
const client = new Anthropic();

const response = await client.messages.create({
  model: "claude-sonnet-5",
  max_tokens: 500,           // hard cap on reply length (Ch. 15: cost/latency)
  temperature: 0.7,          // 0 = deterministic, 1 = default variety, up to 1
  top_p: 0.9,                // optional: nucleus sampling cutoff
  messages: [
    { role: "user", content: "Write a one-line tagline for a coffee shop." }
  ],
});
console.log(response.content[0].text);

5. Picking the right setting for the job

Use caseRecommended temperatureWhy
Data extraction / structured output (Ch. 9)0 – 0.2You want the same correct answer every time, not creative variety
Classification, routing decisions0Consistency matters more than anything — same input, same output
General chat / assistant0.5 – 0.8Natural-sounding, not robotic, but still coherent
Creative writing, brainstorming0.9 – 1.0You explicitly want variety and surprise
Common mistake: setting temperature high "to make it smarter." Temperature does not make the model more capable or more correct — it only makes the output less predictable. For anything where correctness matters (code, math, extracting data), lower temperature is almost always better.

6. Other generation controls worth knowing

ParameterWhat it does
max_tokensHard stop — reply is cut off once it hits this many tokens, even mid-sentence
stop_sequencesCustom strings that immediately end generation if produced (e.g. stop at "\n\n")
Greedy decodingThe special case of temperature=0: always take the single highest-probability token

Key takeaways

  • The model outputs a probability distribution over next tokens, not a single answer — sampling is how one gets picked.
  • Temperature controls randomness: 0 = deterministic/repeatable, higher = more variety and risk.
  • Top-p (nucleus sampling) excludes the improbable long tail before sampling, avoiding truly nonsensical picks even at high temperature.
  • Lower temperature for correctness-sensitive tasks (extraction, classification, code); higher temperature for creative/varied tasks.
  • max_tokens and stop_sequences are the other two knobs you'll set on almost every real API call.
🎯 Your exercise
  1. Make the same Claude API call twice with temperature: 0 and a factual question — confirm you get (nearly) identical answers both times.
  2. Now try the same prompt with temperature: 1 three times — compare the variety in the answers.
  3. Reflect: you're building a pipeline that extracts structured JSON (name, date, amount) from receipts. What temperature would you use, and why?
Understanding check
  1. What does temperature actually control? How much the probability distribution is flattened before picking a token — low temperature = more predictable/repeatable, high = more varied/risky. It doesn't make the model "smarter."
  2. What problem does top-p solve that temperature alone doesn't? It excludes very low-probability ("long tail") tokens from ever being picked, preventing nonsensical outputs even when temperature is high.
  3. Why would you use temperature=0 for a data-extraction task? You want the same correct, consistent output every time — randomness only hurts reliability when there's one right answer.
