Skills vs. Plugins

Claude Code what each is · when to use which · structure & packaging

Why this matters. As you customize Claude Code, you'll accumulate prompts, scripts, and knowledge. Skills and Plugins are the two ways to package that customization so it's reusable and shareable. Confusing them is common; the distinction is really "knowledge" vs. "distribution."

Real-world analogy

A Skill is a recipe card — a focused how-to Claude reads only when the dish is ordered. A Plugin is a boxed kit you hand a friend: it can contain several recipe cards (skills), custom kitchen tools (MCP servers), shortcut buttons (slash commands), and specialist helpers (subagents), all installed together.

What a Skill is

A Skill is a folder with a SKILL.md file: a name, a description, and instructions/knowledge for a specific task. Its superpower is progressive disclosure — only the short description sits in context normally; the full body loads only when the task matches. So you can have many skills without bloating every prompt.

my-skill/
├── SKILL.md          # required: frontmatter + instructions
├── reference.md      # optional supporting files
└── scripts/
    └── helper.js
---
name: pdf-invoices
description: Extract line items from PDF invoices into JSON.
  Use when the user mentions invoices, receipts, or billing PDFs.
---

# Extracting invoice data
1. Read the PDF text.
2. Identify vendor, date, line items, totals.
3. Output JSON matching the schema in reference.md.

The description is critical: it's how Claude decides whether to pull the skill in. Write it as "what it does + when to use it."

What a Plugin is

A Plugin is a distribution package — a bundle you install (often from a marketplace/repo) that can include any mix of:

  • Skills (knowledge)
  • Slash commands (saved prompts)
  • MCP servers (new tools/integrations — Chapter 4)
  • Subagents (specialist agents — Chapter 5)
  • Hooks (automation)
my-plugin/
├── .claude-plugin/plugin.json   # manifest
├── skills/
├── commands/
├── agents/
└── hooks/
The clean distinction: a Skill is one capability (knowledge Claude loads on demand). A Plugin is a shipping container that can hold skills and commands and MCP servers and hooks, installed as a unit.

When to use which

You want to…Reach for
Teach Claude a repeatable procedure/knowledgeSkill
Add a personal shortcut for a repeated promptSlash command (may live in a plugin)
Add a brand-new tool/integration (DB, API)MCP server (Chapter 4)
Share a whole toolkit with your teamPlugin bundling all of the above

Skills vs. plugins vs. CLAUDE.md vs. slash commands

MechanismLoadedBest for
CLAUDE.mdAlways (every turn)Small, always-relevant project facts
Slash commandWhen you type itOn-demand repeated prompts
SkillAuto, when description matchesLarger task knowledge, loaded only when needed
PluginInstalled; its parts load per their own rulesPackaging & sharing many of the above

Note the token angle (ties to Chapter 2): CLAUDE.md always costs tokens; a Skill costs almost nothing until triggered. So big knowledge belongs in a Skill, not CLAUDE.md.

Key takeaways

  • Skill = one on-demand capability (knowledge) via SKILL.md; progressive disclosure keeps it cheap.
  • Plugin = a distribution bundle that can contain skills, commands, MCP servers, subagents, hooks.
  • The description field decides when a skill triggers — write it as "what + when."
  • Put big knowledge in Skills (loaded on demand), not CLAUDE.md (loaded always).
  • Use a Plugin when you want to share a whole toolkit as one install.
🎯 Your exercise
  1. Sketch a SKILL.md (frontmatter + 3–5 steps) for a skill YOU would use — e.g. "explain-this-code" or "js-code-review." Focus on writing a great description ("what it does + when to use it").
  2. Then decide: would you ship it alone as a skill, or bundle it in a plugin with a slash command? Justify in one sentence.
Understanding check
  1. Why put large task knowledge in a Skill instead of CLAUDE.md? Skills load on demand (cheap); CLAUDE.md loads every turn (costs tokens always).
  2. One-line difference between a skill and a plugin? A skill is one capability; a plugin is a package that can contain many skills plus commands, MCP servers, and hooks.
